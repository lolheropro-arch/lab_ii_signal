คู่มือต่อสาย Task 3 · DE10-Lite + ESP32-S3 UNO + MCP3201

ดูภาพรวมก่อนว่าอะไรต่อกับอะไร แล้วต่อจริงตามส่วนที่ 1 และ 2 ทีละเส้น ติ๊กช่องในตารางเมื่อต่อเสร็จ. ขาทั้งหมดตรงกับ fpga/de10lite_pins.tcl ซึ่งโหลดเข้าโปรเจกต์ให้อัตโนมัติ ไม่ต้องเปิด Pin Planner

ภาพรวมทั้งระบบต่อกันแบบนี้

เสียง→แรงดัน 0–3.3 V→MCP3201 · 12 บิต→FPGA · 16 000 ครั้ง/วินาที→บล็อกละ 1024 ค่า (64 ms)→SPI 4 MHz→ESP32-S3→USB→กราฟ + FFT

แบ่งงานใบงานเป็นงานเดียว แต่สายแบ่งได้ 2 ส่วน

Task 3 ในใบงานเป็นงานก้อนเดียว 8 ข้อ แต่สายแยกเป็น 2 ส่วนที่ไม่ยุ่งกัน จึงต่อและทดสอบทีละส่วนได้

ส่วนที่ 1 · เก็บสัญญาณ

ไมค์ → MCP3201 → FPGA (5 สายเข้า JP1). ตรงกับใบงานข้อ 1–2 และ Hint 2: ใช้ ADC ภายนอก, FPGA คุมจังหวะ 16 kS/s, เก็บลง Block RAM

ส่วนที่ 2 · ส่งข้อมูล

FPGA → ESP32-S3 → คอม (6 สายจาก JP1). ตรงกับใบงานข้อ 3–5: ออกแบบ interface และโปรโตคอล, ESP32 รับบล็อกจาก FPGA แล้วส่งต่อทาง USB, Python แสดงผล

ต่อส่วนที่ 2 ก่อน แล้วทดสอบด้วยโหมด test tone (build.bat 2) ซึ่ง FPGA สร้างคลื่นไซน์เองโดยไม่ต้องมี ADC. ถ้ากราฟขึ้น TEST RAMP: OK แปลว่าส่วนที่ 2 ถูกแล้ว ค่อยต่อส่วนที่ 1 แล้ว build ใหม่ด้วย build.bat 0 3201. ถ้ามีปัญหาจะรู้ทันทีว่าอยู่ฝั่งไหน

ก่อนต่อหาขา 1 ของ JP1 ให้แน่ใจ (1 นาที)

JP1 คือ header ตัวผู้ 2×20 ที่มีกรอบพลาสติกดำ อยู่ขอบบนของบอร์ด (header ตัวเมียที่อยู่ใต้มันคือ Arduino ไม่ได้ใช้). ในรูปที่ส่งมา ปลายซ้ายของ JP1 มีเลข 2 พิมพ์ข้างแถวบน จึงน่าจะเป็นขา 1 อยู่แถวล่าง ปลายซ้าย ตามผังนี้ แต่คู่มือ Terasic (Figure 3-18) บอกแค่เลขขา ไม่ได้บอกว่าขา 1 อยู่ปลายไหนของบอร์ด ให้ยืนยันด้วยมัลติมิเตอร์ก่อน

1. เสียบ USB ให้ DE10-Lite
ตั้งมิเตอร์ที่ DC V สายดำแตะ GND ใดก็ได้ เช่นขา GND บน header Arduino ขอบล่างของบอร์ด
2. สายแดงแตะคอลัมน์ 6 แถวล่าง
ได้ 5.0 V = ผังถูก (นั่นคือขา 11). คอลัมน์ 15 แถวล่างต้องได้ 3.3 V (ขา 29)
3. ถ้าไม่ได้ตามนั้น
ลองคอลัมน์ 6 นับจากขวา แถวบน ถ้าได้ 5 V แปลว่าขา 1 อยู่ขวาบน ให้หมุนผังทุกรูปในหน้านี้ 180° (เลขขาเหมือนเดิม)

1JP1 ขา 8 → MCP3201 ขา 7 (CLK)FPGA ส่งนาฬิกา 800 kHz ให้ ADC เลื่อนบิตผลลัพธ์ออกมาทีละบิต การแปลงหนึ่งครั้งใช้ 16 ลูก = 20 µs เสร็จทันในคาบ 62.5 µs ของ 16 kS/s
2MCP3201 ขา 6 (DOUT) → JP1 ขา 10ผลแปลง 12 บิตออกมาทีละบิต (MSB ก่อน) เข้า FPGA เป็นสายเดียวที่ข้อมูลเสียงไหลเข้ามา
3JP1 ขา 7 → MCP3201 ขา 5 (CS)FPGA ดึงขานี้ลงทุก 62.5 µs จากตัวนับคริสตัล 50 MHz ขอบนี้คือจังหวะ sampling จริง ไม่มีซอฟต์แวร์เกี่ยว (ใบงานข้อ 6)
4MCP3201 ขา 8 (VDD) → ราง + บนเลี้ยง ADC ด้วย 3.3 V ไม่ใช่ 5 V เพราะ DOUT ส่งแรงดันสูงเท่า VDD เข้า FPGA ถ้าเป็น 5 V ขา FPGA ซึ่งรับได้ 3.3 V อาจเสีย
5ราง + ล่าง → JP1 ขา 29 (3.3 V)ไฟ 3.3 V ของทั้ง breadboard มาจาก DE10-Lite เส้นเดียว ADC กับ FPGA จึงมีระดับลอจิกเดียวกัน
6ราง − ล่าง → JP1 ขา 30 (GND)กราวด์อ้างอิงร่วม ADC วัดแรงดันเทียบจุดนี้ FPGA ก็อ่าน DOUT เทียบจุดเดียวกัน
7ตัวเก็บประจุ 100 nF คร่อมราง + / − ข้างชิปADC ดึงกระแสเป็นพัลส์ตอนแปลง ตัวเก็บประจุเป็นแหล่งไฟสำรองระยะสั้นข้างชิป ลดสัญญาณรบกวนในบิตล่าง ๆ
8ไมค์ OUT → 1 kΩ → MCP3201 ขา 2 (IN+)สัญญาณเสียงที่จะแปลง ตัวต้านทานจำกัดกระแสถ้าแรงดันเกิน 0–3.3 V (เช่นตั้ง generator ผิด) และแทบไม่กระทบการวัดเพราะตัวเก็บประจุ sampling ใน ADC เล็กมาก
9MCP3201 ขา 1 (VREF) → ราง +, ขา 3 (IN−) และ 4 (VSS) → ราง −VREF 3.3 V ทำให้ 4096 ระดับครอบช่วง 0–3.3 V ที่ไมค์แกว่งพอดี (1 LSB ≈ 0.8 mV). MCP3201 วัด IN+ ลบ IN− จึงต่อ IN− ลงกราวด์ให้เป็นการวัดเทียบกราวด์ธรรมดา
+ไมค์ VCC → ราง + บน, ไมค์ GND → ราง − บนไมค์ใช้ 3.3 V เหมือน ADC แรงดัน DC ของเอาต์พุตไมค์จึงอยู่ราว 1.65 V กลางช่วง ADC พอดี
+สายเชื่อมราง บน ↔ ล่าง (แดงกับแดง, ดำกับดำ)breadboard ส่วนใหญ่รางบนกับรางล่างไม่ได้ต่อถึงกัน ต้องเชื่อมเอง
+JP1 ขา 9 ไม่ต้องต่อเป็นขา DIN สำหรับ MCP3202 เท่านั้น MCP3201 มีช่องเดียวจึงไม่ต้องรับคำสั่งเลือกช่อง

ทำไม S3 ใช้ IO10–IO13

เป็นขา FSPI ประจำชิป ต่อกับ SPI hardware ผ่าน IO MUX ตรง ๆ จึงได้ timing แน่นอนกว่าขาอื่นที่ต้องผ่าน GPIO matrix และอยู่ติดกันบน header มี GND ถัดไปทันที. ห้ามใช้ IO19/IO20 เพราะเป็นสาย USB ของบอร์ด ส่วน IO3/IO46 ชิปอ่านค่าตอนบูต ถ้า FPGA ดึงไว้ S3 อาจบูตผิดโหมด

ทำไม FPGA ใช้ JP1 ขา 1–5

ขาเรียงติดกันไม่มีขาไฟคั่น อยู่ใน I/O bank เดียวที่ 3.3-V LVTTL ต่อกับ ESP32 ได้ตรง ๆ ไม่ต้องแปลงระดับ และมี GND ที่ขา 12 ใกล้ ๆ. แยกจากขา 7–10 ของ ADC เพื่อให้ ADC กับ ESP32 ใช้บัสคนละชุด FPGA จึงสั่งแปลงตามจังหวะของตัวเองได้ตลอดแม้ ESP32 กำลังอ่าน

รันลำดับการเปิดใช้งาน

  1. ต่อส่วนที่ 2 ตามตาราง แล้วเสียบ USB ทั้งสองบอร์ดเข้าคอม
  2. อัปโหลด sketch ลง S3 (ครั้งเดียว): Arduino IDE เปิด esp32/task3_esp32_bridge/task3_esp32_bridge.ino → บอร์ด ESP32S3 Dev Module → Upload. ถ้าไม่เข้า กด BOOT ค้าง กด RST แล้วปล่อย
  3. ดับเบิลคลิก fpga\build.bat (โหมด test tone) รอจนขึ้น DONE แล้ว LEDR0 จะกะพริบ
  4. ดับเบิลคลิก host\run_host.bat คลิกที่หน้าต่างกราฟแล้วกด t ต้องขึ้น TEST RAMP: OK แล้วกด n
  5. ถอด USB ของ DE10-Lite ต่อส่วนที่ 1 แล้วเสียบกลับ รัน build.bat 0 3201 แล้วเปิด run_host.bat อีกครั้ง พูดใส่ไมค์ต้องเห็นกราฟขยับ
